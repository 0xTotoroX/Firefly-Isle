# 知见 / MyOncode：AI Native 前端设计任务书

状态：用户已提出方向；页面结构与视觉方案待提案和审核。本文是本轮设计输入，不是生产实现完成记录。

## 产品与名称

中文名称为“知见”，英文为“MyOncode”，英文大小写固定。产品说明：面向肿瘤患者与家属的全程管理工具。它整合病历整理、治疗追踪、指标管理和疾病信息理解，为回看治疗经过与就诊沟通提供依据；范围包含治疗和随访，不限于诊前整理或晚期患者。

现有基础包括检查、诊断、用药和治疗记录，治疗时间线，化验趋势，症状、副作用、随访、受控分享与导出。基因变异、信号通路、靶点及相关用药知识解读仍是未来规划，本次不生成可用功能入口，不编造疗效或诊疗建议。

产品以专业信息管理与理解支持为主，情绪陪伴不是核心功能。灯塔图标暂时沿用、候选 M 图标未定稿；原型可用文字品牌，不在本次确定新 logo。域名购买、备案、微信资质和生产上线均不在设计执行范围内。

## 用户已明确的方向

- A、B 两种旧方案都不满足当前需要。新提案从需求出发，不要求在两者之间选择、拼接或延续其布局。
- 从 AI Native 的使用方式重新设计。用户带着资料或目的进入，系统根据正在进行的任务呈现相关操作与结果。
- 首页应非常干净、简洁；不要把全部功能、统计数字、指标图、推荐问题和帮助说明堆在首屏。
- 参考日系简约的留白、秩序与克制，让内容容易看见、理解和操作。Kami、Yohaku 等是审美参考，不是必须完整套用的规范。
- 保留有效业务逻辑与后端，在当前项目逐页迁移；成熟版本独立迁仓另行决定，不同时维护两套长期产品实现。

## 本次提案要回答的问题

“首页”先按进入产品后的任务入口设计，不与公开品牌介绍页或登录页混为一谈。首页与现有 /dashboard、/app 的最终路由关系待审核，不在原型里声称已完成路由迁移。

请先围绕“放入报告 → 理解处理状态 → 核对与修正 → 确认保存 → 阅读正式记录”提出一个连贯方案。展示首页、处理中/核对中、保存后这三个主状态。确定的信息直接使用，只有会改变交付范围的关键歧义再询问。

以下是建议验证的交互起点，不是已批准的固定布局：

- 首页以一个主要输入区域承接文字与报告；次级入口能找到已有病历和历史任务，不要求用户记住提示词。
- 操作涉及患者时，当前归属清楚可见；多个患者或新建病历的归属不明时，在保存前确认，不由 AI 猜测。
- 核对时才展开原文、提取字段、缺失项和修改操作。桌面可比较并排核对，手机应重新安排操作，不压缩桌面双栏。
- 结果按内容提供病历、表格、趋势图或摘要；可以直接阅读和操作，不将所有内容困在长聊天记录里。
- 正常首页不默认显示 KPI 卡片、诊疗数据墙、大幅欢迎语、装饰性 AI 状态、推荐提示词墙。真正的错误、阻塞和未完成任务必须清楚可见。

自由提问、自动理解任务和跨功能调度属于拟议体验，不代表当前后端已经支持任意 Agent 工具调用。本轮只模拟与既有功能对应的确定流程，新增行为须在后续实施前确认。

## 信息与状态规则

- 区分报告原文、AI 提取草稿、人工修改和已确认记录。出处可展开查看；来源定位是拟议交互，精确框选能力需后续核实。
- AI/OCR 结果经人工复核后才成为正式记录。状态必须区分处理、待核对、保存中、已保存和保存失败；失败保留输入与更正内容，支持重试。
- 日期、药名、剂量、单位和报告参考范围保持完整；缺失字段留空并说明待补，不补造正常值、日期、诊断、治疗效果或来源。
- 指标高低以该报告的参考范围为依据，范围缺失时不自动给出“正常”结论；不同单位的读数不直接连线比较。
- 操作成功、报告异常、待核对与品牌强调色分别表达含义，不只靠颜色区别。
- 当前病历的基本信息始终明确；初发与各治疗阶段保持归属，免疫组化/基因检测原文不移到无上下文的全局摘要。

## 视觉探索与可用性

用中文文案、可读字号、清楚对比度、对齐和间距表达关系。可探索柔和中性色与少量强调色，不预设最终色值、字体、圆角或单栏/卡片模板。不要为“日系”加纸纹、山水、樱花、竖排文字；不要为“AI Native”加光球、发光线或无意义运行数字。

现有 Web 支持深浅主题、八种强调色和语言切换，这是后续集成需保留的用户能力，不等于必须复制旧截图。首轮重点验证一套默认视觉的桌面/手机，再展示深浅主题和强调色如何兼容；对比度未测量前不宣称通过无障碍认证。

手机保留主要操作与文字可读性；焦点、键盘操作、上传进度、取消、失败重试及减少动态效果需有可观察的设计。动效只帮助反馈与状态衔接。

## 交付与边界

交付可操作的原型、简短取舍说明、状态覆盖与限制。通过人工走查再形成正式设计规范。保留 React 18 / TypeScript / Tailwind 与现有业务/API 边界；本轮不实现 Supabase、OCR/LLM 调用、支付、账号迁移、小程序或生产部署。

新原型只使用 FIXTURES.json。它是专门的设计样例结构，不能直接当作数据库导入或真实 PatientRecord API。所有模拟输出须在原型中清楚标为示例；不生成临床建议。
