# 当前 OpenDesign 交接材料

这份材料用于知见 / MyOncode 的 AI Native 前端原型探索。品牌与产品范围按 2026-10-04 仓库提交 `9fb3122` 核对；首页极简、按任务展开的方向来自本次用户要求。当前交付是设计输入，还没有生成或选定新原型，也没有替换正式前端。

## 交给 OpenDesign 的内容

在 OpenDesign 新建独立原型项目，提供本文件与同目录的 `BRIEF.md`、`FLOWS.md`、`FIXTURES.json`、`REFERENCES.md`，共五个文件。先读 BRIEF，再按 FLOWS 使用虚构数据。文件之间不依赖原仓库或历史设计目录。

不导入 Firefly-Isle 整个仓库，不附带 archive、旧 DESIGN.md、A/B 页面、生产配置或用户病历。AGENTS.md 是本仓库的材料维护地图，不是第六份设计要求。不因附件目录中存在其他文件就自动读取它们。

可直接发送这段任务说明：

> 请使用附带的五份文件，为“知见 / MyOncode”制作可交互的 Web 前端原型。重点展示同一条任务的干净首页、报告处理与核对、确认后的结构化记录，提供桌面和手机布局。遵守 BRIEF 中已确认的产品范围与最新设计方向；具体导航、排版、配色及组件形态由你提出并解释取舍，不沿用旧 A/B 或传统统计 Dashboard 作为默认首页。所有资料均为虚构，OCR、AI 与保存采用明确标注的模拟状态，不连接真实服务。先交付可审查原型、设计理由和状态覆盖说明；不要修改正式产品、创建新后端、发布网站或把未来基因解读做成已可用功能。

## 这次应拿到什么

- 一份可预览、可操作的原型，覆盖 FLOWS 的三个主状态及必要失败态；桌面与手机采用同一份虚构资料。
- 简短设计说明：默认显示什么、为什么需要显示，哪些内容按需展开；AI 结果如何核对并成为正式记录。
- 状态检查结果和已知限制；生成成功不代表可用性、真实服务或生产接入通过。

不要在探索前先写一套声称“最终确认”的 DESIGN.md。原型经用户认可后，再提炼当前设计规范与 tokens。若需正式导入为 OpenDesign 设计系统包，按实际安装版本核对包格式；它与本次五文件任务材料不是同一个交付。

## 审核后如何接入

用户认可原型后，编码 Agent 再读正式仓库的相关模块、接口和适用指令，复用现有 React 组件与服务边界。React 导出只作为待集成代码，按页面验收保存、身份隔离、刷新、分享及导出。微信小程序、原生壳、生产切换和成熟版迁仓单独验收。

仅获准准备这份材料，不表示已批准调用外部模型、安装插件、生成付费内容或实施前端迁移。
