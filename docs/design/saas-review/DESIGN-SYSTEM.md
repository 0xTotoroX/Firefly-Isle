# 病历管理设计系统

版本 1.0，2026-10-02。独立设计评审稿，面向癌症患者与家属的长期病历管理工具。本文不确定最终品牌名称，不连接业务服务，也不修改正式前端。

交付包括：`index.html` 可交互视觉文档板、本文的设计规则、`tokens.json` 的设计变量。直接打开 HTML 即可查看，不依赖远程字体、图标或脚本。设计变量是文档交付物，生产接入应在评审后单独实施。

## DS-00 · 设计方向

深石板灰提供稳定的阅读背景，科技蓝表示主要操作、链接和选中状态。借鉴日系版式的留白与克制：相关内容紧凑，不同任务留开距离；用对齐表达关系，减少多层卡片、反复分割与装饰文字。

1. **内容可读。** 病程正文默认 16 px。药名、剂量、日期、错误原因完整显示，不因空间不足缩小关键文字。
2. **关系明确。** 页面只有一个主要任务和一个同级主操作。来源、历史版本、技术参数按需展开。
3. **结果确定。** 保存过程有状态，失败保留输入。用户确认之前，AI 提取内容标记为待核对。
4. **事实独立。** 用户记录、来源事实和 AI 辅助内容可区分。成功绿色表示操作完成，不表示医学正常。

文档板的标题和样例用于展示系统，不构成产品命名。所有患者、记录、数值均为虚构样例；示例参考区间不能替代真实报告。

| 200 | `#DAE1E9` | `#C6DCFF` | 次一级高亮 |
| 300 | `#B6C2D2` | `#96BDFF` | 次要文字、深色背景链接、焦点 |
| 400 | `#97A7BD` | `#6BA3FF` | 辅助文字、图表强调 |
| 500 | `#64748B` | `#377DFF` | 控件边框、图形强调 |
| 600 | `#43536B` | `#2563EB` | 强边界、主要按钮 |

| 900 | `#121820` | `#172E68` | 页面背景、深蓝底 |

### 语义角色

业务组件使用语义角色，不直接挑选某个色阶。同一个角色只承担一种含义。

| 角色 | 色值 | 规则 |
| --- | --- | --- |
| `background.canvas` | `#0B1119` | 文档或应用外层画布 |
| `background.page` | `#121820` | 主要工作区 |
| `background.surface` | `#1B2430` | 内容面板、菜单背景 |
| `background.raised` | `#2B3748` | 浮层、抬高层 |
| `background.selected` | `#1A3052` | 选中背景 |
| `text.primary` | `#F3F6FA` | 标题、关键内容 |
| `text.secondary` | `#B6C2D2` | 普通说明 |
| `text.muted` | `#97A7BD` | 辅助说明、单位、时间 |
| `text.link` | `#96BDFF` | 文字链接 |
| `border.subtle` | `#293546` | 装饰分区、静态面板边线；不可单独标识输入控件 |
| `border.strong` | `#64748B` | 输入控件与必要边界 |
| `border.focus` | `#96BDFF` | 键盘焦点 |
| `action.primary` | `#2563EB` | 主要操作，搭配白字 |
| `action.hover` | `#1D4ED8` | 主要按钮悬停 |
| `action.pressed` | `#1E40AF` | 主要按钮按下 |

| `action.disabledForeground` | `#97A7BD` | 禁用文字 |

深色表面的抬高层逐步变亮。输入区可使用凹入背景，但必须保留清楚的控件边界。避免依靠阴影区分所有层级。

### 状态色

| 状态 | 前景 | 背景 | 边框 | 使用边界 |
| --- | --- | --- | --- | --- |
| 成功 | `#7DE0B6` | `#14382F` | `#357C63` | 已保存、已核对；不表达病情 |
| 警告 | `#F3CA7A` | `#382C18` | `#8D7140` | 待补充、待核对、日期临近 |
| 错误 | `#FDA4AF` | `#3D232B` | `#A55E6C` | 操作失败；异常值必须配具体方向和范围 |
| 信息 | `#96BDFF` | `#1A3052` | `#547BAD` | 进行中、选中项、一般说明 |

颜色必须配合文字、图标或形状。偏高用“↑ 高于参考范围”，偏低用“↓ 低于参考范围”；不能只给数字染红。正常读数用中性文字“范围内”，避免大面积绿色制造医学保证。

### 对比度

按 WCAG 相对亮度公式计算下列指定色对，保留两位小数：

| 色对 | 对比度 | 用途 |
| --- | --- | --- |
| `#F3F6FA` / `#121820` | 16.46:1 | 正文 / 页面 |
| `#97A7BD` / `#1B2430` | 6.39:1 | 辅助文字 / 内容表面 |
| `#FFFFFF` / `#2563EB` | 5.17:1 | 主要按钮文字 |
| `#96BDFF` / `#1B2430` | 8.21:1 | 焦点 / 内容表面 |
| `#64748B` / `#121820` | 3.75:1 | 输入边框 / 输入背景 |

目标：普通文字至少 4.5:1，大号文字至少 3:1；辨识控件所必需的图形与边界至少 3:1。表格数据与说明默认按普通文字标准处理。上述数字是色值计算，不能替代对完整页面、所有状态与辅助技术的可访问性验收。

## DS-02 · 排版和文案

字体使用系统无衬线，中文优先落在 PingFang SC / Microsoft YaHei。技术标记使用系统等宽字体，不让正文成为终端界面。

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI",
  "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
font-variant-numeric: tabular-nums lining-nums;
```

| 角色 | 字号 / 行高 | 字重 | 使用位置 |
| --- | --- | --- | --- |
| 封面标题 | 56 / 64 px | 600 | 文档封面或介绍页；手机 32–42 px |
| 页面标题 | 32 / 43 px | 600 | 一个页面一个；手机 28 px |
| 区块标题 | 24 / 34 px | 600 | 治疗经过、检验趋势 |
| 内容标题 | 18 / 27 px | 600 | 记录标题 |
| 阅读正文 | 16 / 28 px | 400 | 病程、说明、错误原因 |
| 控件标签 | 14 / 21 px | 500 | 按钮、表单、导航 |
| 辅助说明 | 13 / 20 px | 400 | 来源、单位、次要元数据 |
| 指标读数 | 32 / 38 px | 500 | 单个重点数值，等宽数字 |

关键患者信息不使用 13 px 级别。文档中的 token 标识与尺寸注记可更小，正式产品界面不沿用这些规格标签。

中文使用自然字距，标题可轻微收紧，正文不人为拉开。长段落宽度最多 720 px，每段只讲一个主题。内容需要更多空间时换行或展开，不压缩行高。

文案直接说明动作和结果：

- 操作使用“保存记录”“上传报告”“重新载入”。
- 错误使用“保存失败。输入内容已保留，请重试。”，并针对可修正字段给出具体原因。
- AI 提取使用“AI 已整理 12 项信息，请核对后保存。”，不能声称已经验证、诊断或保证准确。
- 未知数值写“未记录”，未知参考范围写“未提供”。不要显示为 0 或空字符串。
- 日期写 `2026-09-20`，必要时补充具体时分与时区；不要只有“昨天”而无完整时间入口。

## DS-03 · 尺度与布局

### 间距

基础刻度：4、8、12、16、24、32、48、64、96 px。

- 图标与文字：8 px；标签与输入框：8 px。
- 控件内边距：10–12 px 垂直、12–16 px 水平。
- 同组字段：16–24 px；不同任务组：32 px。
- 大区块之间：48–64 px；96 px 仅用于介绍页大段落间隔。
- 默认正文行高 28 px。资料列表行高至少 52 px。

### 圆角与层级

| 角色 | 圆角 |
| --- | --- |
| 标签、细小状态 | 4 px |
| 按钮、输入框 | 8 px |
| 面板 | 12 px |
| 对话框 | 16 px |
| 筛选标签 | 999 px |

静态内容不使用阴影。菜单或浮层使用 `0 8px 24px rgb(0 0 0 / 20%)`，模态弹窗使用 `0 20px 64px rgb(0 0 0 / 40%)`。使用边框与背景建立层级，避免套娃式抬高。

### 响应式

| 视口 | 布局 | 关键规则 |
| --- | --- | --- |
| ≥1024 px | 224 px 侧栏 + 工作区 | 内容最多 1280 px，边距 24–48 px；正文另限 720 px |
| 640–1023 px | 顶部导航 + 工作区 | 次要侧区收起，表单根据内容采用 1–2 列 |
| <640 px | 单列 | 16 px 边距；44 px 最小常用触控区域；无整页横向滚动 |

文档板为了规格比较，个别色值标签、辅助工具使用较小尺寸。正式患者操作使用 44 × 44 px 或更大目标。这高于 WCAG 2.2 AA 的 24 × 24 px 最低要求，不把 44 px 误记为 AA 最低值。

表格可保留局部横向滚动，滚动容器有可访问名称并可获得焦点。不要把表格文字整体缩小。移动端应优先显示指标、结果、单位和异常状态，来源与历史可展开。

## DS-04 · 组件契约

### 按钮

高度默认 44 px，图标 16–20 px，图文间距 8 px。同一任务区一个主要按钮。次要按钮透明背景和明确边框，低频操作可用文字按钮。

原生 `button` 支持 Enter / 空格。跳转使用 `a`，不能把 `div` 伪装成按钮。所有纯图标按钮必须有名称。

保存中显示进行状态，阻止重复提交，但不清除输入。成功后播报结果；失败返回可重试状态。禁用原因放在附近可读说明，不依赖禁用按钮的悬停提示。

### 表单

可见标签绑定输入框，帮助文本通过 `aria-describedby` 关联。必填字段用文字标识。提交后，首个无效字段获得焦点，并有 `aria-invalid="true"` 和具体错误说明。

用户修正输入后消除对应错误。不要在每个按键之后催促式报错。保存失败保留输入，重试只重做当前提交，不重跑已经完成的其他任务。

原生 checkbox / select 优先。开关用于立即生效的二元设置，必须显示名称和当前状态。复杂日历、组合框或模态交互在正式实现时优先采用已有可访问组件能力，不复制文档示例拼装产品框架。

### 状态徽章与筛选

状态徽章是只读文本，无指针手势或假 hover。筛选标签使用按钮，`aria-pressed` 表达是否选中，可通过键盘切换。不得让相同外观同时承担不同行为而无说明。

### 导航

当前页面使用 `aria-current="page"`。文档章节导航使用 `aria-current="location"`。选中项同时改变背景和文字，焦点另有独立轮廓。

Tab 顺序与视觉顺序一致。原生链接不伪装成 tabs。正式页签若采用 tabs 语义，必须完整实现左右方向键、Home / End、`aria-controls` 和 roving tabindex。

### 对话框

使用语义化模态。打开后焦点进入，Tab 不逃出；Escape 关闭，关闭后返回触发控件。删除确认默认聚焦取消，明确说明被删除对象及影响。文档示例使用原生 `dialog.showModal()`。

### 表格、数字与病历语义

表格使用 `table`、列标题 `th scope="col"` 与可读 caption。数字右对齐、等宽显示，单位独立一列。医疗正文和药名完整换行。

显示精度跟随来源，不自动补零来伪造精确度。不同单位不能直接合并趋势，缺失读数不能当零，也不能用连续线跨过缺失数据。参考范围跟随对应报告；颜色不作为诊断依据。

AI 内容必须明确来源与核对状态；确认前不静默替换已核对记录。临时编辑、正在保存、保存成功和保存失败必须可区分，避免界面看似完成但刷新丢失。

## DS-05 · 状态与反馈

| 状态 | 视觉 | 行为 |
| --- | --- | --- |
| 默认 | 稳定背景与清楚文字 | 可发现且可操作 |
| 悬停 | 轻微背景或边框变化 | 不出现唯一的关键操作入口 |
| 按下 | 深一档背景，可选 0.98 缩放 | 不延迟操作 |
| 键盘焦点 | 2 px 蓝色轮廓，外偏移 3 px | 不被裁切，焦点路径符合视觉顺序 |
| 禁用 | 灰色样式 | 实际 `disabled`，附近解释原因 |
| 载入 | 固定占位或旋转图标 + 文字 | 防重复提交，保留原内容 |
| 成功 | 简短结果反馈 | `role="status"` / polite 播报，不强制移动焦点 |
| 错误 | 文字原因 + 可执行操作 | 保留输入，用户处理前持续可见 |
| 空状态 | 当前缺少什么 + 第一项行动 | 首次空白、筛选无结果和载入失败分别说明 |

### 动效

按钮反馈 120 ms，展开 180 ms，弹窗最多 200 ms，缓动使用 `cubic-bezier(0.23, 1, 0.32, 1)`。键盘导航即时执行。动效只用于反馈或状态衔接，不为所有内容加入逐块飞入。

遵循 `prefers-reduced-motion`，关闭旋转、缩放与平移动画。载入文字仍然保留，不能依靠旋转图标作为唯一进行中提示。

### 文档板可体验的交互

- 章节导航与滚动位置指示。
- 网格开关、色值复制、舒适/紧凑行间距。
- 默认/悬停/禁用按钮与表单，筛选标签和导航选中。
- 表单必填校验、保存中、成功和模拟失败；失败保留内容。
- 空状态、错误、载入状态与重试。
- 原生确认弹窗，取消与删除反馈、Escape 关闭和焦点回归。

文档中的保存、导出、删除仅演示状态转换，不执行真实业务，也不把医疗数据持久化到浏览器。

## 验收与开发交接

正式接入前需逐项验证：

1. 390、768、1440 px 下无整页横向溢出，200% 缩放下内容仍可读；表格在局部滚动。
2. 仅用键盘完成导航、输入、提交、重试、弹窗取消，焦点始终可见。
3. 长药名、多行病程、多条检验数据、缺失单位和参考范围可以完整阅读。
4. 保存失败保留输入；重复提交不产生重复记录；临时编辑与已保存状态不混淆。
5. 每个数据图表有文字摘要或等价表格，异常不是只用颜色表达。
6. 所有正常文字、焦点、控件边界按实际背景复核对比度；禁用状态的例外不能套用于辅助说明。
7. 使用屏幕阅读器检查标签、错误、状态播报与对话框焦点。色值计算和 HTML 语义不等于已经通过这项验收。
8. 医疗数据写入、来源核对、权限、账户和服务端失败边界由产品与工程规格继续定义；本设计系统不替代它们。

## 研究依据

以下是本轮打开并核验的官方规范。采用角色、层级与可访问性原则，色值、布局和文档板由本方案独立设计；没有复制组件源码。

- [IBM Carbon：颜色与深色层级](https://www.carbondesignsystem.com/building-blocks/foundations/color/overview)。用于核验语义 token、深色抬高层级、独立 focus / disabled 角色。
- [Radix Primitives：可访问性](https://www.radix-ui.com/primitives/docs/overview/accessibility)。用于核验原生语义、可访问名称、键盘操作与焦点管理的责任边界。
- [W3C：文字最低对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。用于普通文字 4.5:1 和大号文字 3:1 的目标。
- [W3C：目标尺寸最低要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。用于区分 24 px AA 最低要求与本方案为患者采用的 44 px 目标。
