# 临床工作流迁移与验证

本说明对应 `improve-clinical-workflows`。本地代码和隔离数据库验证完成，不代表已推送 GitHub 或部署生产；既有远端迁移记录和线上版本需在发布时重新确认。

## 本次变化

症状/随访新增显式携带 owner，编辑只提交可变字段，更新/删除验证返回行，失败后不会显示成功。追加迁移 `supabase/migrations/20260912051552_clinical_workflow_integrity.sql` 为两表补上 `auth.uid()` 默认值和患者归属 RLS，症状的治疗线必须属于同一患者。

Dashboard 使用两个 `security invoker` RPC：指标按患者、类别、指标代码先选最新检测，再筛异常；随访按每位患者最新就诊的安排计算提醒，保留逾期，排除结疗/失访。未应用迁移时，新版 Dashboard 对相关分区显示读取失败和重试，不会静默展示无记录。

## 本地检查

```bash
npm test
npm run lint
npm run type-check
npm run build
npm run test:database
```

数据库检查需要 Docker 和已缓存的 `postgres:18-alpine`。脚本使用 `--pull never`、`--network none`、内存数据目录和退出清理，只执行相关真实迁移及虚构数据用例；不读取项目凭据，不连接远端。`auth.uid()` 以 JWT subject 会话变量模拟，使用真实 PostgreSQL 角色和 RLS。该检查不是完整 Supabase Auth/PostgREST 端到端测试。

数据库覆盖 owner 新增/更新/删除、跨 owner 拒绝、伪造 owner 拒绝、跨患者治疗线拒绝、空症状/逆序日期拒绝、迟到旧报告不覆盖新检测、跨患者同名指标独立、空新计划替代旧计划、逾期提醒与结疗排除。前端 DOM 检查覆盖日期、错误重试、输入保留、删除确认、患者切换、摘要范围/失效和页签键盘操作。

## 发布顺序

1. 确认目标 Supabase 项目及迁移历史，确认 `001`、`002`、`012`、`013` 对应表/列已存在。历史环境曾手动执行 SQL，不能未经核对直接对全部迁移执行 `db push`。
2. 审核新增 SQL 后，在目标数据库事务内应用这一份追加迁移，再发布新版前端。迁移不重写历史记录；新增检查约束为 `NOT VALID`，保护后续写入，历史异常行需要单独复核。
3. 用专用测试患者验证新增、编辑、删除、跨账号隔离和 Dashboard 最新状态。完成前不得把本地测试结果写成线上验收通过。

遇到回归时，前端回退到上一已验证发布版本；新增 RPC 和索引可保留。不要为了恢复旧界面撤掉 owner/患者归属校验。若历史数据违反新约束，先导出并确认修正方式，不自动改变归属或清理患者数据。

## 设计与当前验证边界

V3 使用纯白/纯黑表面和八色预设，分别定义实色背景、按钮前景、强调文字及临床语义色。预设的双主题正常/悬停文字对比度不低于 4.5:1。病历中治疗时间线先于完整指标表和 AI 分析，分享管理默认折叠。症状常用预设按需展开。症状/随访表单、总览和删除弹层在 390px 中英文浏览器视口下检查无页面横向溢出；桌面和窄屏验证使用真实 React 组件与虚构存储，实际应用的公开 `/demo/record` 也已完成加载检查，未出现控制台 error。未调用真实 LLM、计费或写入患者数据。

构建仍包含既有的 `liquid1.min` 约 512.51 kB 分包警告；本变更未扩大到重写登录 WebGL 背景。V4 候选未切换，原生 App 真机与线上登录后的全链路需随对应发布另行验收。

## 原子用量额度

`20261002111617_atomic_usage_quota.sql` 依赖 `009_usage_ledger.sql`、`010_billing.sql`。先核对目标项目的迁移历史与 `auth.users.is_anonymous` 列，再部署该迁移和两个网关；网关尚未匹配新迁移时会返回错误。迁移撤销旧 `record_usage` RPC 的客户端权限，不能单独回退到旧网关来恢复服务。

`consume_usage` 根据可信身份选择限制：登录 LLM 每分钟60次、匿名 LLM 每分钟10次、OCR 每分钟20次；同时应用套餐的30天滚动额度。没有有效 active/trialing 且未到期订阅的用户使用 free。旧 `LLM_*RATE_LIMIT*` / `OCR_RATE_LIMIT_PER_WINDOW` 环境变量不再决定额度，变更限制需经数据库迁移审核。

输入、模型、密钥配置通过校验后，数据库在同一事务内检查并记录一次上游尝试；上游报错不退回次数。拒绝返回429且不新增台账；RPC 故障或无效响应返回503且不访问模型。设置读写不消耗额度，台账不表示支付扣费。

`npm run test:database` 覆盖上述规则、跨用户隔离、套餐不可由客户端改写、旧记账入口关闭，以及两条真实 PostgreSQL 连接争抢最后一次额度。CI 先拉取官方 `postgres:18-alpine`，再运行原有无网络测试容器。只使用合成数据，未调用线上模型或部署数据库。
