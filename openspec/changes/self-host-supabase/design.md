# Design
Use Supabase self-hosted/v0.8.1 in /opt/firefly-supabase, isolated from existing VPS services. Expose only a loopback gateway through Cloudflare Tunnel at https://supabase.ghibli1024.com. PostgreSQL and service-role credentials never enter frontend assets. Studio/metadata and Realtime/pooler are optional profiles; logs/analytics remain off. Restore public schema, account/identity data, custom auth trigger and storage policies; preserve source exports privately. Validate counts, ownership, login, CRUD and AI/OCR before cutover. Final cutover requires a write freeze and a fresh consistent export.

The preparation now lives with the current SaaS implementation. Keep the cloud configuration in wrangler.jsonc and use frontend.env.example only for an explicit self-hosted preview. Before shipping this frontend, reconcile the target schema with all current migrations and deploy compatible Edge Functions, following docs/operations/record-integrity-release.md. The old production frontend and downloaded functions are historical evidence, not the release source for the integrated application.

Import legacy browser storage only on the configured self-hosted origin. Preserve source credentials, refresh legacy JWTs before enabling routes, and reject legacy JWTs in later auth events too. Remember an import as pending before SDK initialization because the SDK can discard an expired rejected session. Mark completion only after a destination session exists, so a later sign-out cannot resurrect the source identity. Storage failures must not block SDK initialization.
