# Decisions

1. 新增显式提交已认证用户的 ID，兼容现有非空列；数据库同时提供 `auth.uid()` 默认值并用 RLS 验证患者/治疗线归属。更新仅包含可变字段，写后 select 确认确有目标行，避免零行更新仍显示成功。
2. `calendar-date.ts` 统一本地日期格式、有效日期和日历天差。日期型业务不从 UTC 时间戳截断，也不把跨夏令时的 23/25 小时当成不同天数。
3. 仪表盘最新异常通过 `security invoker` RPC 按患者、category、item_code 选择最新检测日期，再判断异常；迟到导入旧报告不会覆盖当前状态。最新随访只取每份患者最近一次就诊记录，下次日期为空表示未安排；逾期安排仍可见，结疗/失访患者不进入提醒。
4. 仪表盘非核心分区单独降级并标明不可用，不把权限/网络/缺迁移错误变成 0 或“无记录”。基础病历计数失败显示整页重试。
5. 症状/随访页面按 patientId 隔离表单生命周期，载入失败时保留说明与重试，保存失败保留输入。删除需明确确认，重复操作在请求中禁用。摘要包含时间范围内持续的症状，并在数据/条件变更时重新生成，避免复制过期内容。
6. V3 继续生效：primary 为品牌色，foreground 用于实色按钮，text 用于可读强调文字；warning/critical/low/success 与个人强调色独立。治疗时间线移到完整检验表和 AI 分析前，不改变 PDF/PNG 的数据覆盖；分享控制默认折叠，详情首屏优先呈现病历内容。

# Validation and delivery

使用无网络临时 PostgreSQL 容器执行真实迁移、owner CRUD、越权/跨患者归属拒绝和最新状态查询。前端完成 DOM 行为、类型、Lint、全量测试、构建和浏览器页面检查。测试数据均为虚构数据。

完成整个变更后提交一个 Conventional Commit；不推送或迁移远端数据库。追加迁移需随未来发布先行应用，未应用时仪表盘新查询显示可恢复的分区不可用状态。
